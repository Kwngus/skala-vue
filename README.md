# 날씨 대시보드

Vue 3로 만든 날씨 웹앱
도시를 검색하고 실시간 날씨 확인하는 기본 기능에서 시작해서,
대기질/일출일몰/5일 예보 같은 부가 정보도 같이 보여주게
만들었다. 
즐겨찾기하여 자주 보는 도시 모아두거나, 전세계 도시를 지도에서 찾아보고 서로 비교하는 기능도 존재한다.

## 실행 방법

```
npm install
npm run dev
```

날씨 데이터를 받아오려면 OpenWeatherMap API 키가 필요하다.
 프로젝트 루트에 `.env` 파일 만들고 아래처럼 넣으면 실행된다.

```
VITE_OPENWEATHER_API_KEY=발급받은키
```

## 사용한 기술

Vue 3 Composition API, Vue Router, Pinia, Axios, Leaflet, Element Plus.

Router는 요구사항대로 지연 로딩, 동적 라우트(`/weather/:cityId`),
Catch-all 구현. View는 3개 추가 — 도시 목록(`/forest`), 즐겨찾기
(`/favorites`), 전세계 지도(`/explore`).

Pinia는 요구사항인 온도 단위 토글 store 외에 도시 데이터 캐싱 store,
즐겨찾기 store, 비교함 store까지 총 4개 추가함. 캐싱 store는 홈에서
상세 페이지로 넘어갈 때 API를 또 안 부르게 하려고 만든 건데, 처음엔
이 생각을 못 해서 페이지 옮길 때마다 API를 계속 다시 호출하고
있었다.

Axios는 OpenWeatherMap 기본 API 외에 대기질(Air Pollution), 5일
예보 추가로 붙임. 그리고 OpenWeatherMap이 아닌 완전히 다른 서비스
(Sunrise-Sunset API, 일출일몰용)도 연동.

UI Library는 Element Plus 사용. `el-tag`로 온도/대기질 뱃지,
`el-dialog`로 도시 비교 모달, `el-button`으로 버튼 일부 구현.

## 페이지 구성

- `/` — 메인 화면. 현재 위치 기반 날씨 표시, 즐겨찾기 도시 미리보기
  포함.
- `/forest` — 전체 도시 목록. 검색, 지도, 통계, 최근 검색어 기록,
  도시 직접 추가 기능까지 포함.
- `/favorites` — 즐겨찾기한 도시만 모아보는 페이지.
- `/explore` — 전세계 도시를 지도에서 보고, 최대 3개까지 담아서
  비교 가능.
- `/weather/:도시id` — 상세 페이지. 습도/풍속/대기질/일출일몰/5일
  예보 표시.
- `/about` — 프로젝트 소개 및 트러블슈팅 기록.
- `/showcase` — 실습 단원별로 만든 것 정리, 그때 만든 컴포넌트를
  실제로 그 페이지 안에서 다시 불러와서 보여줌.

## 요구사항 외 추가한 것

**전세계 지도 및 도시 비교함**
`/explore`에서 Leaflet로 세계지도를 띄우고, 9개 도시를 마커로 표시.
마커 누르면 팝업으로 상세보기/비교함에 담기 선택 가능. 최대 3개까지
담아서 하단 트레이에서 확인하고, "비교하기" 누르면 도시별 온도/풍속/
대기질/날씨상태를 나란히 보여주는 모달이 뜬다. 원래 `/forest`
지도는 좁은 박스였는데, `/explore`는 전체화면으로 따로 분리해서
만들었다.

**다크모드**
Pinia store에 `theme` 상태 하나 추가하고, `body`에 `data-theme`
속성을 붙여서 CSS 변수 값 자체를 바꾸는 방식으로 구현. `localStorage`에
저장해서 새로고침해도 유지되게 함. 색상 하나하나를 하드코딩한 게
아니라 역할 기반 변수(배경/텍스트/보더 등)로 미리 만들어둬서, 나중에
전체 디자인 톤을 바꿀 때도 이 변수 값들만 고치면 자동으로 적용되는
구조로 짬.

**위치 자동감지**
브라우저의 `navigator.geolocation`으로 현재 좌표 받아서, 그 좌표로
OpenWeatherMap에 직접 날씨 조회. 위치 권한 거부하거나 실패하면 그냥
기존 서울 기준 화면으로 자연스럽게 넘어가게 처리함. 위치를 못 가져와도
화면이 깨지지 않게 신경 씀.

**대기질 마우스 인터랙션**
현재 위치 대기질(AQI)에 따라 마우스 움직일 때 화면에 다른 효과가
나옴. 공기 좋으면 반짝이는 입자가 마우스를 따라다니고, 나쁘면 뿌연
안개 같은 게 마우스 주변에 낌. 순전히 재미로 넣은 기능인데, 실제
대기질 데이터를 시각적으로 표현해보고 싶어서 만들었다.

**검색 히스토리 및 온도 통계**
`/forest`에서 도시 검색하고 엔터 치면 최근 검색어가 `localStorage`에
기록되고, 아래 칩으로 보여줌. 처음엔 타이핑할 때마다 기록했는데
한글 조합 중이라 "ㅂ", "부", "부산"처럼 중간 글자까지 다 저장되는
문제가 있어서, 엔터 눌렀을 때만 기록하도록 고침. 통계는 그날 전체
도시의 평균/최고/최저 온도를 계산해서 상단에 보여줌.

**도시 직접 추가**
`/forest`에서 도시 이름/온도/날씨상태/습도/풍속을 직접 입력해서
목록에 추가할 수 있음. 새로고침하면 사라지는 임시 데이터지만, 원래
1일차 실습(Vue Syntax)에서 만들었던 "본인 데이터 추가" 기능을 최종
앱에도 옮겨 넣고 싶어서 나중에 따로 붙였다.

## 트러블슈팅

**1. 데이터랑 함수를 착각**
버튼 눌렀는데 "configStore is not a function" 에러 발생. configStore는
여러 값이랑 함수가 같이 들어있는 객체인데, 그 객체 자체를 클릭
이벤트에 넘겨버린 게 원인. `@click="configStore.toggleWindUnit"`처럼
객체 안의 실제 함수를 지정해서 해결.

**2. 오타**
네비게이션 스타일을 분명 맞게 짰는데 화면에 하나도 안 먹힘. 콘솔
에러도 없음. `class="nav=links"`라고 쓴 부분에서 하이픈(-) 자리에
등호(=)가 들어가 있었던 게 원인. 에러가 없다고 코드가 맞는 게 아니란
걸 배움.

**3. 라이브러리 기본값이 만든 오차**
지도 마커가 실제 도시 위치보다 살짝 오른쪽 아래로 밀려서 찍힘.
Leaflet 마커 생성 시 `iconAnchor`를 지정 안 했더니 기본값(아이콘
왼쪽 위 모서리)이 좌표 기준점이 된 게 원인. `iconAnchor: [16, 16]`으로
중심을 맞춰서 해결.

**4. 기본 스타일코드에 대한 이해부족**
카드 개수 바뀔 때마다 화면 전체 폭이 줄었다 늘었다 함. 원인은 Vite가
프로젝트 생성 시 기본으로 넣어준 `body { display: flex; place-items:
center }`. 직접 작성한 코드가 아니라 처음부터 있던 코드였음.

**5. 증상과 실제 원인이 다른 층위에 있던 경우**
온도가 28~33도인데 뱃지가 파란색으로 표시됨. 온도 판단 함수 자체는
정상이었는데, 템플릿에서 `:type="tempTahType"`이라고 오타를 내서
존재하지 않는 변수를 참조하고 있던 게 원인.

## 느낀 점

오늘 가장 많이 부딪힌 버그는 복잡한 로직 문제가 아니라 사소한
오타였다. -와 =, Tag와 Tah처럼 눈으로도 잘 안 걸러지는 차이가 기능을
통째로 망가뜨렸다. 이 경험으로 콘솔에 에러가 없다고 안심하지 않고,
화면에 실제로 어떻게 렌더링되는지 눈으로 확인하는 습관을 들여야겠다.
